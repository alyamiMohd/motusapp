# Project state (2026-10-28)

## Stack
- `public/`: plain HTML, CSS, ES modules (no build, no framework). Pages: index (Home), workouts, weeks, connect, shortcut.
- `worker/`: Cloudflare Worker (ES modules) + D1 (SQLite). Serves `public/` as static assets and `/api`. Deployed with `wrangler` 4.x (dev dependency; the only one).
- Tests: Node 20+ (24 on this laptop and in CI), no test framework; `tests/d1.mjs` runs the worker's SQL on `node:sqlite`.

## Architecture
```
Browser (public/) ── same origin ──► Worker (worker/index.js) ── D1 (worker/schema.sql)
  account.js: sign-in, pull (ETag), push imports       ├─ auth.js: codes (hash, 10 min, 5 tries, rate limits), session cookie
  store.js/merge.js: sources + priority                 ├─ hevy.js: key encrypted (HEVY_SECRET), /v1/workouts/events in steps
                                                       ├─ /api/upload: Shortcut token (hash) → merge into source "health"
                                                       └─ cron */30: Hevy steps for a few accounts, cleanup
iPhone: Motus Shortcut ── POST /api/upload (Bearer mh_…) daily via a Shortcuts automation
Sign-in codes: the owner's Gmail via an Apps Script web app (GMAIL_SCRIPT_URL + GMAIL_SECRET); Brevo, then Resend, are fallbacks if set
```

## The Motus Shortcut (v2, `fd29eb5`)
- Generated by `node tools/shortcut/build.mjs` (123 actions, Apple's own actions only) → `tools/shortcut/dist/` (git-ignored). Signed by the **Sign Shortcut** workflow (`gh workflow run sign-shortcut.yml --repo alyamiMohd/motusapp`; artifact `motus-shortcut`: `Motus.shortcut` + `motus-shortcut-signing.mobileconfig`, kept 3 days). D-022.
- Finish opens `shortcuts://run-shortcut?name=Motus&input=text&text=<upload url>|<token>`. With input: saves `motus.txt`, reads 30 days, uploads, returns to Motus. Without input (automation/tap): reads `motus.txt`, reads 2 days (Dietary Calories and Weight 7 days), uploads. D-026.
- Payload `v: "2"`: `steps` and `active` are raw samples `date time|value|(unit|)source`; the server sums per source per day and keeps the largest source (D-025). `calories` grouped by day with Fill Missing; `weight`, `sleep` raw (sleep deduped by source as before).
- Type labels as Shortcuts stores them: "Dietary Calories" (the picker shows "Dietary Energy"), "Active Calories".
- To ship a new version: edit build.mjs → test → push → run the workflow → download → put both files in `public/setup/` (not committed; in `.git/info/exclude`) with a TEMPORARY `_headers` block (`application/x-apple-aspen-config` for the profile; octet-stream + attachment for the Shortcut) → deploy → owner: profile, trust, add, Copy iCloud Link → set `SHORTCUT_URL` and the link in `shortcut.html` → remove setup files and the headers block → deploy → commit.
- **Current state:** v2 files live under `/setup/` (version 3624d6f6); `SHORTCUT_URL` still the v1 link `eb6a8c01…`.

## API
| Route | What |
|---|---|
| POST /api/auth/start, /api/auth/verify, /api/auth/logout | email code sign-in; cookie `motus` (HttpOnly, SameSite=Lax, Secure on https, 1 year) |
| GET /api/me · DELETE /api/me | status (Hevy, Health) · delete the account and everything |
| GET /api/data | `{ me, sources: {id: {imported, data}}, workouts: [...] }`, ETag = users.changed |
| PUT/DELETE /api/sources/:id | device-imported sources: manual, apple, mfp, csv, hevy, strong |
| POST/DELETE /api/hevy · POST /api/hevy/sync | connect (validate + first step) / disconnect · next sync step |
| POST/DELETE /api/health | new Shortcut token (replaces the old) + upload URL / disconnect |
| POST /api/upload | the Shortcut's upload: `{v: "2", steps, calories, active, weight, sleep}` (v2 raw samples with source) or v1 daily lines, or Health Exporter JSON/`health_b64`, or `{days}` |
| POST/DELETE /api/android | (2026-10-29) new HC Webhook token `mc_…` (stored `hc:`+sha256, replaces the old Android token only) + `{url, token, settings}` (HC Webhook's SettingsExport JSON) / disconnect (token + source `hc`) |
| POST /api/upload/hc | HC Webhook's JSON (`steps`, `active_calories`, `nutrition`, `weight`, `sleep`, `timezone`), Bearer `mc_…`, no cookie; `fromHealthConnect` in health.js; source `hc` |
| GET/PUT /api/profile | name, username, avatar (PUT: fields left out stay; "" or null clears; 400 bad, 409 taken/reserved; 60/h) |
| GET /api/u/:username · GET /u/:username | public: name, username, avatar only · the page `public/user.html` (absolute paths, no nav) |
All cookie-authenticated non-GET requests require `Origin` = the app's origin. `/api/me` also returns `profile {name, username, photo: bool}` and `android {connected, last_upload}`.

## Sources (priority, highest first)
manual > health (Shortcut) > hc (Health Connect) > apple (file) > mfp > csv > hevy_live (connected Hevy, computed in the browser from the server's workouts) > hevy (CSV) > strong.
