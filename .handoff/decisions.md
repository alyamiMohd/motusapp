# Decisions

| ID | Decision | Alternatives considered | Why | Who, date |
|---|---|---|---|---|
| D-001 | Browser-only app: every import is read and stored in the visitor's browser (localStorage); no server, no accounts | A multi-user service with logins and a database; a "fork this repo and add your secrets" template like the personal `motus` | Health data is sensitive; no server means nothing to leak, no hosting costs, no sign-up, and it runs on free GitHub Pages. A template needs a GitHub account, so it's not for the general public | Claude (default, stated to the owner), 2026-10-26 |
| D-002 | A fresh repo with no git history from `motus` | Fork or copy the history | `motus` history contains the owner's health exports and personal data | Claude, 2026-10-26 |
| D-003 | Imports from exports (files) plus the Hevy API; no automatic background sync | Phone automations uploading somewhere | Nothing can receive uploads without a server (D-001). Hevy allows browser calls (checked: `access-control-allow-origin: *`, `api-key` header allowed), so "Sync Hevy now" is one tap with a saved key | Claude, 2026-10-26 |
| D-004 | Each app is a separate source; when two have the same day and metric: hand entry > Apple Health > MyFitnessPal > spreadsheet > Hevy > Strong; a day's workouts come from one app, never added across apps | Add everything up; newest import wins | Avoids double counting (MyFitnessPal also writes into Apple Health; people move between Hevy and Strong) and lets each app be removed on its own | Claude, 2026-10-26 |
| D-005 | Full-history exports (Hevy, Strong) replace that source; partial ones (Apple Health, MyFitnessPal, CSV, hand entry) merge in | Always merge; always replace | A full export is the truth (deleted workouts disappear); partial exports must not wipe older days | Claude, 2026-10-26 |
| D-006 | Apple Health raw export: per day take the single source with the highest total (steps, sleep, food energy, active energy); weight = last reading; a night belongs to the wake-up day (sleep ending after 18:00 counts to the next day) | Sum all sources (double counts iPhone + Watch); reimplement Apple's per-interval merge | Close to what the Health app shows, simple and testable. Known approximation, written on the README | Claude, 2026-10-26 |
| D-007 | Apps without a direct import (Google Fit/Health Connect, Fitbit, Garmin, Samsung Health, Oura, Withings) go through a CSV template, said honestly on the page | Claim support; build untested importers | No reliable format knowledge or sample files for them; better to say "not yet" | Claude, 2026-10-26 |
| D-008 | Public-audience settings: kg/lb, week starts Sunday or Monday, visitor's own time zone; defaults: steps 8000, sleep 7 h, calories < 2000, workouts 4/week, training days Mon/Tue/Thu/Fri | Keep the owner's Riyadh/Sunday/1500 kcal settings | The owner's settings were personal; the rules themselves (R-007, R-008) are unchanged | Claude, 2026-10-26 |
| D-009 | Content-Security-Policy on every page (own scripts only, `connect-src` self + `api.hevyapp.com`), all imported text escaped, `no-referrer` | No CSP | Imported files are untrusted; the Hevy key must not be sent anywhere else | Claude, 2026-10-26 |
| D-010 | Pages served from `main` root with `.nojekyll`; tests run on GitHub Actions (`.github/workflows/test.yml`) | A Pages deploy workflow | No build step, so branch hosting is simplest | Claude, 2026-10-26 |
| D-011 | Pages are indexable (no `noindex`), with a description | Keep `noindex` from the personal site | The app is meant to be found and used publicly | Claude, 2026-10-26 |
| D-012 | Automatic sync runs in **each person's own copy** of a public template repo (`alyamiMohd/motus-sync`): phone uploads via `repository_dispatch`, Hevy every 3 h, one AES-256-GCM file (gzip, random IV, 32-byte key `MOTUS_KEY`) published on their own GitHub Pages; the app fetches and opens it with the key saved on the device. Supersedes D-003's "no automatic background sync" | A central job in the owner's repo (would store strangers' health data in a public repo and need a shared write token); commits of an encrypted file (repo bloat); a private repo + gist (more setup) | The owner asked for GitHub Actions "for now"; this is the only way GitHub Actions can serve many people without a server: nobody's data sits in someone else's repo, and nothing readable is published | Owner (GitHub Actions), Claude (design), 2026-10-26 |
| D-013 | Later phase: real accounts with **email-code** sign-in on a small server | Private sync code only; Sign in with Apple/Google | Owner's choice; lets people without GitHub use automatic sync | Owner, 2026-10-26 |
| D-014 | The job reads the phone upload from `GITHUB_EVENT_PATH`, never from `env`; it prints no numbers; it refuses to overwrite data its key can't open (except a manual "Start over") | Passing the upload as an env variable | A live run showed GitHub prints step env in the public log | Claude, 2026-10-27 |
| D-015 | The Motus Shortcut builds on the **Health Exporter & Shortcuts** app (daily totals) and sends Base64 text (`health_b64`), the same proven steps as the owner's own shortcut | Built-in "Find Health Samples" (reported to over-count when grouping; can't be tested by Claude) | Reuses a chain that already works daily on the owner's phone | Claude, 2026-10-27 |
